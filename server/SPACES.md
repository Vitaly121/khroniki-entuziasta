# Пространства посетителей и правки предметов: формы данных

Документ для части 2 (3D-коридоры, комнаты, расстановка). Таблицы — `server/schema2.sql` (не меняются); этап 12 добавил `hall_styles` — `server/schema3.sql` (см. в конце).
Клиентские нормализаторы, которым надо доверять при чтении: `Backend.spaces.normRoom(room)` и `Backend.spaces.normPlace(place)` в `backend.js` — они превращают любое значение из базы в полную форму ниже (недостающие поля получают значения по умолчанию, лишние отбрасываются). `Backend.spaces.get(id)` уже возвращает нормализованные `room` и `place`.

Единицы: длины — **метры**, углы — **градусы**, цвета — `#RRGGBB`.
Изображения хранятся как **путь в бакете** `spaces` (не URL): `<uid>/<случайное>.webp|jpg` у посетителя, `book/<случайное>.webp|jpg` у правок книги. Публичный адрес: `Backend.spaces.url(path)` = `<supabaseUrl>/storage/v1/object/public/spaces/<path>`; для чужого или битого пути возвращает `""`. Проверка пути: `Backend.spaces.pathOk(path)` (регэксп `^(book|<uuid>)\/[A-Za-z0-9_-]{4,80}\.(webp|jpg|png)$`). Картинки уже уменьшены клиентом до ≤1600 px по длинной стороне и ≤ ~600 КБ. Для текстур грузить с `crossOrigin="anonymous"` (публичный бакет Supabase отдаёт CORS `*`).

## Система координат комнаты

Комната — прямоугольник `w` × `d`, высота `h`. Начало координат — **центр пола**. Ось `+x` — на восток (вправо, если стоять в двери лицом внутрь), ось `+z` — на юг, к двери, `y` — вверх.
Стены: `n` — северная, напротив входа (z = −d/2); `s` — южная, **в ней дверь** (z = +d/2, проём по центру стены); `e` — восточная (x = +w/2); `w` — западная (x = −w/2). Вход в комнату всегда через южную стену.
Ширина проёма двери в части 1 не задана; редактор рисует его ≈14 % ширины стены — для 3D разумно 1,2 м × 2,2 м по центру `s`.

## `spaces.room` (jsonb < 4 КБ)

```json
{
  "v": 1,
  "size": "m",            // "s" | "m" | "l" — пресет
  "shape": "room",        // "room" | "gallery" (вытянутая)
  "w": 9, "d": 7,         // метры; ВЫЧИСЛЯЮТСЯ из size+shape (см. таблицу), хранятся для удобства
  "h": 3.5,               // 3 | 3.5 | 4
  "walls": {
    "mode": "one",        // "one" — все стены = walls.all; "each" — у каждой своя (n/e/s/w)
    "all": { "img": "<uid>/ab12….webp", "fit": "tile", "color": "#E9E4DA", "tile": 2 },
    "n": { … }, "e": { … }, "s": { … }, "w": { … }   // есть только при mode "each" (могут быть и при "one" — тогда игнорировать)
  },
  "floor": { "img": "", "fit": "tile",    "color": "#8B6F55", "tile": 2 },
  "ceil":  { "img": "", "fit": "stretch", "color": "#F4F2EE", "tile": 2 }
}
```

Размеры пресетов (w × d, метры), высота выбирается отдельно:

| size | room   | gallery |
|------|--------|---------|
| s    | 6 × 6  | 10 × 4  |
| m    | 9 × 7  | 14 × 5  |
| l    | 12 × 9 | 20 × 6  |

У галереи длинная сторона — `w` (по оси x), дверь всё равно в южной (длинной) стене по центру.

**Поверхность** `{img, fit, color, tile}`:
- `img` — путь в бакете или `""` (нет картинки → только цвет);
- `fit` — `"tile"` «повторять как обои» | `"stretch"` «растянуть как фото»;
- `color` — запасной цвет (используется, когда `img` пуст, не загрузилась или ещё грузится);
- `tile` — для `tile`: ширина одного повтора картинки в метрах (0,5…6, по умолчанию 2); высота повтора — по пропорции картинки. Редактор пока не даёт менять `tile`, всегда 2.

Как получить поверхность стены `k` ∈ {n,e,s,w}: `walls.mode==="each" && walls[k] ? walls[k] : walls.all`.
`stretch` для стены — картинка на всю стену (w × h или d × h); для пола/потолка — на весь прямоугольник. Пропорции при `stretch` не сохраняются (так видит автор в превью); если для 3D нужно «cover» — договориться отдельно.
По умолчанию: стены `#E9E4DA`, пол `#8B6F55`, потолок `#F4F2EE`, `fit:"tile"`.

Обложка карточки на этаже: первая непустая картинка из `walls.all, n, e, w, s` (`list()` отдаёт её как `cover`, URL).

## `space_objects` и `space_objects.place` (jsonb < 1 КБ)

Строка предмета: `id, space, owner, name (≤80), descr (≤1200), img (путь или ""), place, sort`.
Порядок показа — по `sort` по возрастанию (редактор держит 0…N−1; при равенстве — по `id`). Не более 24 предметов.

`place` — как показывать и, необязательно, где стоит:

```json
{ "kind": "wall" }                                       // картинка на стене, место — автоматически
{ "kind": "wall", "wall": "n", "u": -1.25, "y": 1.5 }    // поставлено вручную
{ "kind": "ped" }                                        // предмет на постаменте, автоматически
{ "kind": "ped", "x": 1.4, "z": -0.8, "r": 90 }          // поставлено вручную
```

- `kind`: `"wall"` («картина на стене») | `"ped"` («предмет на постаменте»). Если поля нет — `"wall"`.
- Для `wall`: `wall` ∈ n|e|s|w; `u` — смещение центра картины вдоль стены от середины стены, метры, **плюс — вправо, если стоять лицом к этой стене**; `y` — высота центра картины от пола, метры (по умолчанию 1,5). Ручное место считается заданным, только если есть и `wall`, и числовое `u`.
- Для `ped`: `x`, `z` — центр постамента в координатах комнаты (метры); `r` — поворот вокруг вертикали, градусы, 0 = лицевая сторона смотрит на юг (к двери), по часовой стрелке если смотреть сверху; целое 0…359. Ручное место — если оба `x` и `z` числа.
- Значения округляются до 0,01 м. Всё прочее `normPlace` выбрасывает.
- Сброс на автоматическое место: записать `{kind}` без координат (`Backend.spaces.updateObject(id,{place:{kind}})`).
- Смена `kind` в редакторе части 1 сбрасывает координаты.
- Любой `update`/`insert` предмета не-админом возвращает одобренное пространство на проверку (триггер базы) — после сохранения расстановки показать статус (`Backend.spaces.get(id).status`).

## `obj_edits.data` (jsonb < 8 КБ; id ≤ 40) — правки предметов книги

Ключ строки `id` = id предмета книги (`o12`, `n41`, `cards`…) или id нового предмета: `x` + 10 знаков `[a-z0-9]`.
В `data` — **только изменённые поля**:

```json
{
  "name": "Чайник с отбитым носиком",   // строка ≤120
  "ret":  "Возвращается в Красоту.",     // подпись «где вещь возвращается», ≤2000
  "n":    12,                            // номер записи дневника (должен существовать в BOOKDATA.book)
  "h":    "kr",                          // зал: kv pr id sv dv ot se n kl kr | hb («База Героев · А») | hb2 («База Героев · Б», с этапа 12)
  "img":  "book/ab12….webp",             // картинка вместо книжной
  "hide": true,                          // скрыть от посетителей
  "new":  true,                          // новый предмет (только у id на «x»; тогда name и h обязательны)
  "pos":  { "h": "kv", "x": 3.2, "z": -7.5, "r": 0 }   // ЧАСТЬ 2: место в 3D-музее
}
```

`pos` (для части 2, части 1 только сохраняет его при правках): координаты **мира музея** (`museum.js`, метры, как у `pedestal(o,x,z)`), `h` — зал, к которому относится место (если зал предмета изменился и не совпадает с `pos.h`, место игнорировать), `r` — поворот, градусы. Нет `pos` — автоматическое место.

Как правки применяются (app.js, при старте, ждём ≤1,5 с, при сбое — исходные данные):
`__APP.OBJ_ORIG` — исходные предметы книги; `__APP.OBJ_ALL` — с правками, включая скрытые; `__APP.OBJS` (тот же массив, что `BOOKDATA.objs`, его получает `Museum.mount`) — без скрытых, с новыми. У изменённых объектов есть служебные флаги: `_ed` (есть правка), `_fresh` (новый или переехал в другой зал — нуждается в автоматическом свободном месте), `_new`, `_hide` (только в `OBJ_ALL`). `__APP.imgOf(id)` возвращает URL хранилища для правленых картинок. `__APP.edits()` — текущие правки по id; `__APP.applyEdits(map)` — применить заново.

## Права и статусы (решает база)

`spaces.status`: `pending` («на проверке») | `approved` («опубликовано») | `hidden` («скрыто»); `note` — замечание автора сайта (≤300), меняет только админ.
Видят: одобренные — все; свои — автор; всё — админ. Пространство посетителя для 3D-ссылки `#space-<id>`: `Backend.spaces.get(id)` бросает `not_found`, если оно не видно этому посетителю.
В объекте, который возвращает `get()`: `mine` (автор — текущий посетитель), `canEdit` (автор или админ), `author` (имя), `count`, `cover`, `objects[]` (с `url` картинки и нормализованным `place`).

## Адреса части 1

`#space-<uuid>` — просмотр (сейчас 2D-развёртка; в части 2 — вход в комнату), `#space-edit-<uuid>`, `#space-new-<этаж>`, `#spaces-mine`, `#spaces-review`, `#objs-all`.

## Часть 2 (3D) — что сделано поверх этих форм

- `Backend.spaces.world(floor)` — всё для 3D-этажа: одобренные пространства этажа и свои (любого статуса), с `objects[]`, `mine`, `canEdit`; порядок — по `created_at`. `Backend.spaces.place(objId, place)` — записать `place` и вернуть `{obj, status}` (статус пространства после триггера базы). `Backend.objEdits.setPos(id, pos|null)` — записать или снять `data.pos`, не трогая остальные правки.
- Мир этажа (`museum.js`, `Museum.mount(el,{world:{floor,spaces,enter,url,onObj,onLift,save,msg}})`): лобби с лифтом у z=0, коридор шириной 3 м вдоль −z, двери по очереди слева (чётные) и справа; комната стоит южной стеной (`s`, дверь 1,2 × 2,2 м по центру) к коридору. Координаты `place` — ровно как выше (центр пола, +z к двери).
- Автоматические места: картины — слотами по стенам n, e, w, s (по обе стороны двери), если не хватает — уже и в два ряда; постаменты — сеткой не ближе 1,0–1,3 м от стен и 1,5 м друг от друга, не в зоне двери; ручные места (`wall`+`u`, `x`+`z`) важнее.
- «Обои» (`fit:"tile"`) — повтор шириной `tile` м, высота повтора по пропорции картинки; «растянуть» — на всю поверхность. Текстуры ≤2048 px (на телефоне и в облегчённом режиме ≤1024, картинки предметов ≤1024/512), грузятся у двери, освобождаются вдали; не загрузилась — цвет `color`, у предмета — карточка с названием.
- Присутствие в мирах: `hall` = `f:<этаж>` (коридор) или `s:<uuid>` (комната), новые необязательные поля `w` (мир, `f:<этаж>`) и `hn` (название); у музея книги их нет. `Live.museum().others(world)` фильтрует по `w` (без аргумента — все, как раньше).
- Адреса: `#floor-17/3d` (и `#floor-m1/3d` для −1) — пройти по этажу; `#space-<uuid>` — сразу в комнату (чужое неодобренное — отказ); `#space-plan-<uuid>` — прежняя 2D-развёртка.

## Этап 12: `hall_styles.data` — оформление залов музея книги (jsonb < 8 КБ)

Таблица `hall_styles` (`server/schema3.sql`): `id` — код зала (`kv pr id sv dv ot se n kl kr hb`), `data`, `updated_by`, `updated_at` (их ставит база). Читают все, пишет только админ (`is_admin()`).
Картинки — публичный бакет `spaces`, папка `halls/<код зала>/<случайное>.webp|jpg` (≤ 2 МБ; клиент уменьшает до 2048 px и ~1,2 МБ). Политика вставки в `halls/` — в schema3.sql.

```json
{
  "wall":  { "color": "#335577", "img": "halls/kv/ab12….webp", "mode": "tile" },   // все четыре стены зала
  "floor": { "color": "#8B6F55", "img": "",                    "mode": "stretch" },
  "ceil":  { "color": "#F4F2EE" },
  "paintings": [ { "img": "halls/kv/cd34….webp", "title": "Поле у дома", "wall": "w", "u": -3, "w": 1.4, "h": 1.05, "y": 1.6 } ],
  "light": "warm",            // warm | cool | neutral
  "note":  "Подпись автора"   // ≤300, показывается под названием зала при входе
}
```

- Все поля необязательны; нет поля — как задумано в `museum.js`. Пустой объект в базе не хранится (строка удаляется = «Сбросить к исходному»).
- Проверка при чтении (`Backend.hallStyles.norm(data, id)` и `Museum.hallStyleValid` в 3D): неверное отбрасывается, зал не ломается. `color` — `#RRGGBB`; `img` — путь `halls/<этот зал>/…` или картинка сайта `img/….webp|jpg|png`; `mode` — `tile` («повторять», плитка шириной 2 м, высота по пропорции картинки) или `stretch` («растянуть» на всю стену/пол/потолок).
- Поверхность: только цвет — сразу; картинка — грузится, когда посетитель в этом зале или соседнем, ≤ 2048 px (телефон и облегчённый режим ≤ 1024), вдали освобождается; до загрузки и при битой картинке — `color`, а без цвета — прежний вид.
- Стены зала (как в комнатах посетителей): `n` — напротив входа, `s` — у входа, `e` — справа, `w` — слева, если стоять во входе лицом в зал. Для залов анфилады вход — со стороны предыдущего зала (взгляд вдоль −z); для «Базы Героев» — проём из «Предметов» (взгляд вдоль +x). Перегородка между залами — две стороны: `n` предыдущего и `s` следующего, оформляются раздельно.
- Картины: до 12 на зал; `u` — сдвиг центра от середины стены, м, плюс — вправо, если стоять лицом к стене; `y` — высота центра, м; `w`×`h` — рамка места, м (0,2…6). Фото вписывается целиком, пропорции сохраняются. Картина, перекрывающая проём (в стенах `n`/`s` анфилады по центру проход 3 × 3 м, в «Квартирах» — дверь в коридор квартир слева, в «Предметах» — проём в «Базу» справа), отодвигается вбок, а если не помещается — поднимается над проёмом. Нажатие на картину открывает её крупно.
- Если у зала есть `paintings`, прежние картины зала не строятся (в «Святилище» — тёмные полотна, в «Семье» — шесть пейзажей, в «Красоте» — галерея в рамах); иначе — как раньше (`PAINT` в app.js).
- `hb` оформляет «Базу Героев · А» (вход, арсенал). «База Б» сохраняет свою роспись — её оформление не меняется.
- `light` подмешивается к «запечённому» свету поверхностей зала (тёплый — желтее, холодный — синее, нейтральный — приглушает цвет).
- Загрузка при старте вместе с `obj_edits`, ждём ≤ 1,5 с; сбой или опоздание — прежний вид. API: `Backend.hallStyles.{load, save(id,data), remove(id), uploadImage(file,hall), removeImages(paths), norm, resolve, url}`; `save` и `remove` сами удаляют из хранилища картинки, которые больше не нужны. 3D получает `Museum.mount(el,{hallStyles})` с готовыми адресами (`resolve`).
- Интерфейс: `hallstyle.js` (грузится только по кнопке) — «Оформление залов» в панели автора на странице музея и в музее в режиме «расстановка». Кнопки: «Сохранить» (и музей сразу перезапускается с новым видом), «Применить без перезагрузки» (показать черновик в 3D без сохранения; при закрытии окна черновик убирается), «Сбросить к исходному».

## Этап 12: что автор сайта может и не может редактировать в музее книги

Можно (без кода, из интерфейса сайта; права проверяет база — `obj_edits`, `hall_styles`, хранилище):
- **Любой предмет каталога** (745 предметов книги и добавленные): название, подпись, запись дневника, зал (включая `hb` и `hb2`), картинку, «скрыть/показать» — «Все предметы» (`#objs-all`), кнопка «изменить» в карточке предмета, «Добавить предмет».
- **Положение в 3D** любого предмета зала (на постаменте): «расстановка» в залах анфилады, «Базе А» и (с этапа 12) «Базе Б» — «поставить здесь», «повернуть», «вернуть на автоматическое место». Невыставленный предмет получает постамент там, где его поставили.
- **Новые предметы** в любом зале, с картинкой; встают на свободное место автоматически, а если в зале не хватает места — в расстановке помечены «не выставлен: в зале нет свободного места — поставьте вручную».
- **Удалить** добавленный предмет («Удалить предмет» — строка и его картинка удаляются); книжный — только скрыть или «Вернуть как было».
- **Вид залов**: стены, пол, потолок, картины, свет, подпись — «Оформление залов».

Нельзя (это обстановка, а не предметы каталога; меняется только в `museum.js`):
- мебель, витрины, стеллажи, лампы, двойники, таблички с названиями залов, тезисы в «Идеях», экраны «Двойников», полка эссе в «Клубе»;
- «База Героев»: арсенал у входа, эмблемы и надписи арен, ринги, стенды, роспись «Базы Б» (оформление `hb` меняет стены, пол и потолок «Базы А»);
- квартиры ветки («Headliner», «Маршала Захарова») и их фотографии — данные `FLATS` в `museum.js`;
- форма и размеры залов, проёмы.

Встроенные экспонаты (показывают предмет каталога особым образом, а не на постаменте): открытки на кухонном столе «Квартир» (`cards`), часы в «Святилище» (`o19`, при его скрытии — другой предмет с «секундной стрелкой»/«часами»), тетрадь в «Отце». Их название, подпись, картинку и «скрыть» править можно; в расстановке своего зала они помечены «встроенный экспонат» и не переставляются. Если такой предмет перенести в другой зал, он получает там обычный постамент (с этапа 12; раньше не появлялся).
